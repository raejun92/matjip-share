# 슬라이스 18: 관리 페이지 (유저 삭제)

> 상태: 구현 완료 (E2E 32 통과 — 프로덕션은 Vercel 환경변수 등록 후 활성화)
> 배경: 사용자 피드백 — "유저를 지우는 기능은 없나? 마스터 계정은?"

## 동작 규칙

1. `/admin` 페이지 (메인 UI에서 링크 없음 — URL 직접 접근).
2. **비밀 문구(ADMIN_KEY)** 입력 → 서버 API가 검증. 문구 없인 목록 조회·삭제 불가.
3. 유저 목록: 이름·색·핀 개수. **삭제** 버튼 → 인라인 확인 → 핀 포함 삭제.
4. 삭제는 서버에서 **service role 키**로 실행 (RLS 우회). anon의 users 삭제 차단은 유지 —
   일반 사용자는 여전히 계정을 못 지운다.
5. 삭제된 유저의 세션(localStorage)은 다음 접속 시 무효 → 이름 입력 화면 (기존 규칙 4 재사용).

## 환경변수

- `ADMIN_KEY` — 관리자 비밀 문구 (서버 전용)
- `SUPABASE_SERVICE_ROLE_KEY` — Supabase 관리자 키 (서버 전용, 절대 NEXT_PUBLIC 금지)
- 로컬은 로컬 스택 값, 프로덕션은 Vercel 환경변수 (사용자가 직접 등록)

## 인수 기준

| # | 기준 | 검증 방법 |
|---|------|----------|
| AC1 | 잘못된/누락 키 → 401, 올바른 키 → 유저 목록(핀 수 포함) | E2E |
| AC2 | 삭제 → 유저·핀 제거, 목록 갱신 | E2E |
| AC3 | 삭제된 유저의 기존 세션은 재접속 시 이름 입력 화면으로 | E2E |
