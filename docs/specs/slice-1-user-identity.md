# 슬라이스 1: 이름 입력 → 고유 색상 배정

> 상태: 구현 완료 (테스트 23 + E2E 2 통과)
> PRD 근거: §6.1 사용자 식별, §6.2 색상 배정, §7 화면 1

## 목표

처음 접속한 사람이 **이름만 입력하면** 고유 색상을 배정받고, 재접속 시엔 입력 없이 바로 지도로 간다.
이 슬라이스가 끝나면: DB `users` 테이블 ~ 이름 입력 화면까지 세로로 관통하는 동작하는 앱.

## 사용자 스토리

- 나는 처음 접속했을 때, 이름만 입력하면 바로 시작할 수 있다.
- 나는 내 고유 색상을 배정받고, 그 색을 화면에서 확인할 수 있다.
- 나는 다시 접속했을 때, 이름을 또 입력하지 않아도 된다.

## 동작 규칙

1. **첫 접속**: 이름 입력 화면 표시. 이름 제출 → `users`에 (name, color) 저장 → localStorage에 내 user id 기억 → 메인으로 이동.
2. **색상 배정**: 사전 정의된 고대비 팔레트(10색)에서 **아직 사용되지 않은 색을 순서대로** 배정. 10명 초과 시 팔레트 처음부터 재사용.
3. **기존 이름 입력**: 이미 존재하는 이름을 입력하면 **그 사용자로 이어서 사용** (새로 만들지 않음). 친구끼리 쓰는 앱이므로 사칭 방지는 하지 않음 (PRD 트레이드오프).
4. **재접속**: localStorage에 user id가 있으면 입력 화면을 건너뛰고 메인으로. 단 DB에서 해당 id가 사라졌으면 localStorage를 비우고 입력 화면으로.
5. **유효성**: 이름은 공백 제거 후 1~12자. 빈 이름 불가.

## 인수 기준 (Acceptance Criteria)

| # | 기준 | 검증 방법 |
|---|------|----------|
| AC1 | 팔레트에서 사용되지 않은 색을 순서대로 배정한다 | 단위 (TDD) |
| AC2 | 팔레트 소진 시 처음부터 재사용한다 | 단위 (TDD) |
| AC3 | 이름은 trim 후 1~12자만 유효하다 | 단위 (TDD) |
| AC4 | 새 이름 제출 시 users에 name+color가 저장된다 | 통합 (로컬 Supabase) |
| AC5 | 기존 이름 제출 시 새 행을 만들지 않고 기존 사용자를 반환한다 | 통합 (로컬 Supabase) |
| AC6 | 첫 접속 → 이름 입력 → 색상 확인 → 재접속 시 입력 화면 스킵 | E2E (Playwright) |

## 데이터 모델 (마이그레이션)

```sql
create table users (
  id         uuid primary key default gen_random_uuid(),
  name       text not null unique,
  color      text not null,
  created_at timestamptz not null default now()
);
-- 로그인 없는 앱: anon 역할이 읽기/쓰기 가능해야 함
-- RLS는 켜되 anon에 select/insert 허용 정책
```
